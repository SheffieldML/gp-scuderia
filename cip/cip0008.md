# CIP-0008: Deep GP tier: stacked layers with stochastic bounds

## Status

- [x] Proposed - Initial idea documented
- [ ] Accepted
- [ ] In Progress
- [ ] Implemented
- [ ] Closed

## Summary

Add a separate tier for deep Gaussian processes. The tier is separate because the existing suite assumes a model is one kernel, one likelihood and one approximation with a deterministic objective. A deep GP is a composition of layers, and its objective is a bound that, in most implementations, can only be estimated by Monte Carlo. The same suite cannot carry both without blurring what a failure means: a bug, an unsupported feature, or sampling noise.

The tier compares implementations through three kinds of check: reductions to models already in scuderia (one layer is a sparse GP), estimates that must agree within Monte Carlo error, and held-out predictive quality on shared tasks. It does not compare bound values between implementations that use different bounds.

## Motivation

- Several implementations exist, with different inference schemes. GPc (`CDeepGp`, GPc CIP-0035) uses doubly stochastic variational inference on SVGP layers, with per-layer mean maps and a choice of inducing family. PyDeepGP (`SheffieldML/PyDeepGP`, package `deepgp`, built on GPy 1.15 or later) implements the collapsed, psi-statistic bound of Damianou and Lawrence (2013), with variational auto-encoded and multi-view variants. GPyTorch ships a `DeepGP` model and GPflux provides deep GP layers on GPflow, both using doubly stochastic inference; I believe this but have not verified it against the pinned versions in `ci/`. GPJax has no deep GP. GPy has none apart from PyDeepGP.
- A user asking "which package should I use for a deep GP" has no comparison.
- GPc CIP-0035 reports that depth matters on compositional data (a three-layer model reaches test RMSE 0.229 where the best one-layer sparse model reaches 0.92 on the prototype task). A tier that tests this claim across packages tests whether the benefit is a property of the model or of one implementation.

## Detailed Description

### Admission rule

CIP-0005's rule applies. Two additions:

1. **A deep benchmark must say how it handles Monte Carlo error.** Either the estimate is compared within a stated number of standard errors, or the comparison is deterministic by construction (a reduction, or a shared frozen noise tensor).
2. **A benchmark that compares bound values is admitted only between implementations whose bounds are the same quantity.** Two ELBOs built differently (collapsed psi-statistics against doubly stochastic) are not compared. They are compared through predictions.

### Tier mechanics

- Benchmarks carry `tier: deep` and `requires: {models: [deep_gp]}`. A framework file declares `models: [deep_gp]` only after it passes the reduction check below.
- Deep cases run in their own CI job and workflow, scheduled by default. They are slower and more likely to be flaky, and a failure should not block the main suite.
- The registry adds `models.deep_gp` under the reserved section, as CIP-0003 does for tags awaiting a round trip. The tag moves into `types` after two frameworks round-trip a document.

### Wire format

Depends on the backlog task `variational-and-mcmc`, which reserves `inference: vi` and its `variational` block. A deep GP document extends it:

```yaml
model:
  type: models.deep_gp
  layers:
    - kernel: {type: kern.rbf, variance: 0.5, lengthscale: 1.0}
      inducing: {family: points, z: [...]}
      mean_map: {type: linear, weight: [...]}      # identity or PCA projection
      q_u: {mean: [...], chol: [...], whitened: true}
      output_dim: 5
    - kernel: {...}
      inducing: {...}
      output_dim: 1
  likelihood: {type: likelihoods.gaussian, variance: 0.01}
  inference: vi
  variational:
    num_samples: 10
    seed: 3
```

Rules:

- Layer input dimension must equal the previous layer's `output_dim`, and the first must equal the width of `data.x`.
- `q_u` is whitened by default, as in GPc and GPflux. A framework that uses a non-whitened parameterisation converts in its adapter.
- `mean_map` is explicit, because GPc fixes mean maps \(P_\ell\) and GPflux uses linear mean functions between layers; the same document would otherwise mean different models.
- The inducing family is per layer. Frameworks that support only points refuse other families with `UnsupportedByFramework`.
- Hidden-layer variance scaling (GPc's `chi/(L-1)`) is not a wire field. It is an initialisation heuristic, and the document carries the resulting kernel variances.

### Checks, in order of strength

1. **`deep_one_layer_is_sparse`.** A one-layer deep GP with the optimal \(q(\mathbf u)\) has a bound equal to the collapsed sparse bound. Compare it with the `dtcvar` log likelihood from the existing examples. This is deterministic and needs no Monte Carlo. It is the gate for declaring `models: [deep_gp]`.
2. **`deep_elbo_mc_agreement`.** Evaluate the ELBO at fixed parameters for a two-layer model with a shared document, repeated with \(R\) independent seeds. Two frameworks agree if the difference of means is within four combined standard errors. This applies only between frameworks with the same bound (GPc, GPyTorch and GPflux). PyDeepGP is excluded by the second admission rule.
3. **`deep_frozen_noise`.** Where a framework accepts the hidden-layer noise tensor (GPc: `setFrozenEps`), the ELBO is deterministic, and agreement is checked to ordinary tolerance. This is the strongest deep check and is available for few frameworks, so it is declared an optional operation, not part of the contract. Reporting it does not penalise frameworks that lack it.
4. **`deep_prediction`.** Predictive mean and variance at test inputs from \(R\) independent sample sets, compared within combined Monte Carlo error. PyDeepGP is included here, because predictions are defined for any deep GP.
5. **Gradients.** Cross-framework gradient comparison is not meaningful for stochastic objectives. The check is per-framework self-consistency: automatic or analytic gradient against finite differences with common random numbers. The result is reported per framework and not as agreement between frameworks.
6. **Trained comparison.** Deferred to the training sub-CIP (CIP-0004 step 2). The task is the composite task of GPc CIP-0035 (10-dimensional input, target a nonlinear function of a 2-dimensional projection), with test RMSE and NLL over seeds, comparing one, two and three layers. Initialisation is shared (PCA mean map, random inducing subset pushed through the mean maps).

### Packages to test, in order

| Package | Role | Notes |
|---|---|---|
| GPc `CDeepGp` | Reference implementation of the doubly stochastic bound with frozen-noise support | The only package that can be checked deterministically (check 3) |
| GPyTorch `DeepGP` | Same bound family, autodiff | First external peer for check 2 |
| GPflux on GPflow | Same bound family, whitened layers, linear mean functions | Pin against the GPflow version in `ci/` |
| PyDeepGP | Collapsed psi-statistic bound, GPy-based | Not installed from PyPI; install from the git repository and pin a commit. Compared through predictions only |
| GPmat `deepGP-matlab` | Historic reference | Defer; reachable through the Octave route if useful |
| GPJax | No deep GP | Record `null` |

### What is not claimed

- No benchmark asserts that two implementations should give the same trained model. Deep GP training has many local optima, and the implementations differ in bounds and defaults.
- The tier makes no claim about which inference scheme is better. It reports where schemes agree and where they do not.

## Implementation Plan

1. Finish the backlog task `variational-and-mcmc` (single-layer `vi` in the wire format). This CIP depends on it.
2. Extend the schema and the reserved registry section with `models.deep_gp`; add negative fixtures for each rule.
3. Add `tier` to the benchmark loader and a separate `deep` CI workflow.
4. Add the GPc adapter first, since it can express every field. Add golden `deep_one_layer.yaml` (check 1) and `deep_two_layer.yaml` with its frozen noise tensor.
5. Add GPyTorch and GPflux adapters. Pin and confirm install against `ci/`.
6. Add checks 2 and 4. Add check 3 as an optional operation.
7. Add PyDeepGP (git-pinned) for check 4.
8. Write the trained-comparison sub-CIP.

## Backward Compatibility

Additive. No existing document, benchmark or adapter changes. The new CI job is independent of the main workflow.

## Testing Strategy

- Check 1 is the conformance gate for the tier.
- Monte Carlo checks record \(R\), the standard errors, and the seeds, so that a failure can be reproduced and a marginal pass is visible.
- Negative fixtures for the layer-dimension rule, missing `mean_map`, non-whitened `q_u` without a conversion, and unsupported inducing families.
