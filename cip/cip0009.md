# CIP-0009: Linear basis mean functions (universal kriging) on the wire

## Status

- [x] Proposed - Initial idea documented
- [x] Accepted - Approved 2026-11-28
- [x] In Progress - Started 2026-11-28 on branch `cip0009-linear-basis-mean`
- [ ] Implemented
- [ ] Closed

## Summary

Add a `mean.linear_basis` type to the optional `mean` field of the interchange format. It states a prior mean of the form \(F(x)\beta\) for a stated basis \(F\), and it states explicitly how \(\beta\) is treated: fixed, profiled out, marginalised under a flat prior, or marginalised under a Gaussian prior. The four treatments give different log likelihoods and different predictive variances, so the choice is part of the semantics, not a provenance detail.

## Motivation

CIP-0001 decided that `mean` carries `mean.constant` now and "further mean types later". CIP-0007 then identified the first concrete need: `DiceKriging` and `kergp` fit a linear trend, and the CIP commits to refusing such models until a mean tag exists, never approximating them with a constant.

The frameworks already differ on this point:

- **R (`DiceKriging`, `kergp`).** The trend is linear in its coefficients, specified by an R formula. The coefficients are not optimised alongside the kernel hyperparameters. They are profiled out by generalised least squares, \(\hat\beta = (F^\top K_y^{-1} F)^{-1} F^\top K_y^{-1} y\), and predictive variance includes the extra term for uncertainty in \(\hat\beta\) (the universal kriging correction). We recalled this from the package documentation and then checked it against the `DiceKriging` 1.6.1 source: `logLikFun` reports the profiled (concentrated) log likelihood, and `predict.km` returns the latent variance plus the universal kriging correction, without the noise.
- **GPy.** The mean is a `Mapping` with parameters optimised jointly with the kernel and noise. The coefficients are point estimates and carry no predictive uncertainty.
- **GPc and GPmat.** Only a constant bias is stored. There is no mapping abstraction.

A single tag called "linear mean" would hide these differences. Two frameworks could each claim support, report different log likelihoods for the same document, and both be correct under their own convention. The format has to say which convention a document means.

This follows the principle behind the existing refusal rule: an adapter that cannot realise a field raises, and it does not substitute something nearby.

## Detailed Description

### Model

For targets \(y \in \mathbb{R}^n\), basis matrix \(F \in \mathbb{R}^{n \times p}\) with rows \(F(x_i)^\top\), kernel matrix \(K\) and noise variance \(\sigma^2\), write \(K_y = K + \sigma^2 I\) and \(A = F^\top K_y^{-1} F\). The prior mean is \(F\beta\).

### Wire form

```yaml
mean:
  type: mean.linear_basis
  basis:
    type: basis.polynomial
    powers: [[0, 0], [1, 0], [0, 1]]   # one multi-index per column: 1, x1, x2
  beta:
    mode: profiled                     # fixed | profiled | flat_prior | gaussian_prior
    value: [...]                       # fixed: the coefficients; others: absent
    prior_mean: [...]                  # gaussian_prior only
    prior_cov:  [[...]]                # gaussian_prior only
```

The basis is a list of multi-indices over the input dimensions, not an R formula or a callable, so every runner can build \(F\) without sharing a parser. `basis.polynomial` covers the intercept, linear and quadratic trends that `DiceKriging` supports. Other basis types (for example `basis.columns`, selecting input dimensions only) can be added later without changing the `beta` semantics.

### The four treatments of beta

| `beta.mode` | Meaning | Log likelihood reported |
|---|---|---|
| `fixed` | \(\beta\) given on the wire, no inference | \(\log \mathcal{N}(y; F\beta, K_y)\) |
| `profiled` | \(\beta\) replaced by its generalised least squares estimate | \(\log \mathcal{N}(y; F\hat\beta, K_y)\) |
| `flat_prior` | \(\beta \sim \mathcal{N}(0, vI)\) with \(v \to \infty\); the divergent \(-\tfrac{p}{2}\log v\) term is dropped (restricted likelihood) | \(\log \mathcal{N}(y; F\hat\beta, K_y) - \tfrac12 \log\lvert A\rvert\) |
| `gaussian_prior` | \(\beta \sim \mathcal{N}(m_0, S_0)\) | \(\log \mathcal{N}(y; Fm_0, K_y + F S_0 F^\top)\) |

Predictive mean at \(x_*\) is \(F_*\beta + k_*^\top K_y^{-1}(y - F\beta)\), with \(\beta\) replaced by \(\hat\beta\) in the two estimated modes. Predictive variance is the zero-mean variance for `fixed`. For `profiled` and `flat_prior` it adds \(r^\top A^{-1} r\) with \(r = F_* - F^\top K_y^{-1} k_*\), the universal kriging term. For `gaussian_prior` it adds \(r^\top (A + S_0^{-1})^{-1} r\). Whether predictive variance includes the observation noise follows the existing wire runner contract.

`profiled` and `flat_prior` give identical predictive means and variances. They differ only in the reported log likelihood, which is why both exist: `DiceKriging` reports the former, and the restricted form is the one that remains a proper density comparison when the number of coefficients varies.

### Exactness and cross-framework realisation

`gaussian_prior` is equivalent to adding a kernel \(F S_0 F^\top\) and a fixed mean \(F m_0\). A framework with no mean abstraction can therefore realise it if it has a kernel of the form \(\phi(x)^\top S \phi(x')\). GPc and GPmat have bias and linear kernels, which express the polynomial basis of degree one with a diagonal \(S_0\). Quadratic and non-diagonal cases need a new kernel type or are refused. This path is a realisation detail of an adapter, not a wire concept: the wire states the model, and the adapter chooses how to compute it.

`flat_prior` as a limit of `gaussian_prior` is numerically poor, and adapters must not realise it with a large finite \(v\) without stating the resulting error. Profiled GLS or the closed-form restricted likelihood is the correct computation.

### Interaction with other fields

- `mean.linear_basis` is exact-GP only in 0.1 (`approximation` absent or `ftc`). Profiling or marginalising \(\beta\) under DTC, FITC or PITC has no agreed definition across frameworks, so the schema rejects the combination until one is chosen.
- `mean` and `normalizer` remain mutually exclusive, as decided in the `mean-and-normalizer` task.
- `mean.constant` with value \(c\) is `mean.linear_basis` with `powers: [[0, ...]]` and `beta.mode: fixed`. Existing documents are unchanged, and adapters keep `mean.constant` as the primary form.

## Implementation Plan

1. **Schema and overview.** Add `mean.linear_basis`, `basis.polynomial` and the `beta` modes to the schema, `docs/overview.md` and `registry/types.yaml`. The default for a document that omits the field is unchanged.
2. **Reference computation.** Write a NumPy reference that computes all four log likelihoods and predictive moments from \(F\), \(K\) and \(\sigma^2\), independent of any framework. Goldens use it as `x-reference` for modes GPy cannot produce natively.
3. **Goldens.** Add one golden per mode on a small problem with a degree-one polynomial in two inputs, plus a quadratic case. Add a golden where `profiled` and `flat_prior` differ in log likelihood but agree in predictions.
4. **Adapters.**
   - GPy: realise `fixed` with a `Linear` mapping whose weights are fixed. Realise estimated modes by computing the GLS quantities from the model's \(K_y\); GPy does not provide them. Report which mode it used.
   - GPc and GPmat: realise `gaussian_prior` through bias and linear kernels where the basis allows it. Refuse otherwise, with a clear message. Do not map any mode onto the constant bias unless the basis is the intercept alone.
   - R (`DiceKriging`, `kergp`): map `profiled` natively. Realise `flat_prior` by adding the \(-\tfrac12\log\lvert A\rvert\) term in the adapter.
   - GPflow, GPyTorch, GPJax: refuse until mapped.
5. **CIP-0007 update.** Replace the linear-trend refusal with support for `profiled`, once item 4 lands.

## Backward Compatibility

The change is additive to 0.1. A document without `mean` keeps the zero-mean meaning, `mean.constant` is unchanged, and the new type is refused by any adapter that does not list it in `extras`.

## Testing Strategy

- Each mode's log likelihood and predictive moments are checked against the NumPy reference at tight tolerance, because the computation is deterministic.
- A property test checks that `gaussian_prior` with a very large `prior_cov` approaches `flat_prior` up to the dropped \(-\tfrac{p}{2}\log v\) term, which confirms that the two conventions are related as stated.
- A property test checks that `profiled` and `flat_prior` give the same predictions.
- Adapter tests fail if an adapter returns a result for an unsupported mode or basis instead of refusing.
- The R adapter is checked against `DiceKriging` output, with the log likelihood convention confirmed from the package source before any tolerance is set.
